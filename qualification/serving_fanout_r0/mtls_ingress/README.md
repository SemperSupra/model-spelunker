# R13 — Real mTLS ingress identity + per-certificate and global limits

Scope: [RDTE #316](https://github.com/SemperSupra/model-spelunker/issues/316), reuse [R12 #351](https://github.com/SemperSupra/model-spelunker/pull/351) and original R10 [#350](https://github.com/SemperSupra/model-spelunker/pull/350). This is an **off-the-shelf nginx** behavior test, not a new proxy, admission service or model scheduler.

**Hypothesis:** A loopback HTTPS nginx server requiring a trusted client certificate can make the concurrency budget depend on **cryptographically verified peer certificate fingerprint** (nginx `$ssl_client_fingerprint`) rather than caller-supplied source IP or `X-Tenant`/authentication header. A second `$server_name` limit caps total requests across identities in the single-server experiment. Hard cap: 2 each certificate, 4 globally; two independent synchronized trials: (A) three simultaneous requests from **one** client certificate, requiring exactly two admissions / one rejection; (B) nine simultaneous requests from **three** different client certificates (three requests each), requiring exactly four global admissions / five rejections with no certificate exceeding two admissions. All offers must precede first completion in each trial. Unauthorized or wrong-CA clients should fail closed. This is certificate-identity quota, **not an independently validated mapping from workcell certificate to tenant authority**.

**Experiment:** On one disposable public CPU GHA runner, generate new self-signed CA and three client certificates locally with OpenSSL (keys NEVER uploaded/logged); test exact pinned Ollama 0.34.1/Qwen3:1.7b on loopback via existing nginx 1.24.x. Pre-warm model; 3 then 9 near-simultaneous requests with a barrier and deterministic 64 output-token budget; no retries. Preserve red/blue mock tests of swapped `X-Tenant`, absent cert, wrong trust chain, duplicate identity, arrival skew, missing output accounting and over-admission. Record only sanitized JSON policy IDs, HTTP statuses, times, exact server/model and nginx config/package identity; never store certificate PEM/private keys or raw prompts. Reuse existing R10 hot queue and R12 edge admission patterns without writing another runner.

**Promotion caveats:** `$ssl_client_fingerprint` represents the TLS client certificate, **not** a tenant unless governed certificate issuance/revocation/mapping is independently admitted. Multiple certs for one tenant could multiply quota. `$server_name` is a local nginx listener budget, not distributed fleet admission. Direct backend path bypass remains; deny-by-default traffic topology must be qualified under private IaC ownership. This experiment DOES NOT prove queue priority, fairness, starvation freedom, reliable restart, GPU capacity or BigMac/TrueNAS performance. Package version recorded but apt not reproducibly pinned. Failures retained, no production actions, no private hosted GHA minutes.
