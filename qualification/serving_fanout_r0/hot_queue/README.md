# R10 — Native Ollama queue/admission boundary (public CPU)

**Authority:** [Model Spelunker RDTE #316](https://github.com/SemperSupra/model-spelunker/issues/316) and streaming parent [PR #332](https://github.com/SemperSupra/model-spelunker/pull/332). Reuses exact current public Ollama/Qwen3 pinned release and streaming frontend; direct model requests only, not agent/tenant or a production governor.

**Source-backed hypothesis:** Pinned `ollama/ollama@v0.34.1:server/sched.go` Git blob SHA `e31fedc57477b2028192de941396538dbc52f9b7` branches in `getRunner`: an already-loaded compatible runner takes `req.useLoadedRunner(runner,...)`, while only a missing/reloading runner enters `pendingReqCh` with nonblocking send and `ErrMaxQueue`. Pinned `envconfig/config.go` blob `0379a2aec2a9573d542deb840766a93694f63ffe` sets `OLLAMA_NUM_PARALLEL` (default 1) and `OLLAMA_MAX_QUEUE` (default 512). This means the scheduler's pending queue capacity should not be assumed to bound requests on the **hot model path**. This observation is consistent with upstream [Ollama issue #7758](https://github.com/ollama/ollama/issues/7758), but exact-version live evidence is required.

**Live RED:** Launch disposable loopback-only Ollama 0.34.1 Qwen3:1.7b, configured `OLLAMA_NUM_PARALLEL=1`, `OLLAMA_MAX_QUEUE=1`, `OLLAMA_MAX_LOADED_MODELS=1`. Warm the model, then synchronize six independent real streamed requests using a barrier. Record exact request-submission spread, accepted HTTP 200 vs rejected HTTP 429/503, first token, completion and token counts. No retries, secrets, private hosts, or user prompts.

**Classification:** If all six requests were offered before the first completed and more than two eventually completed with HTTP 200, `EXCESS_REQUESTS_COMPLETED_OUTSIDE_GLOBAL_1_PLUS_1_BOUND`. That establishes the **configuration is not a global at-most-two-request admission guarantee** in this scenario; it does not itself locate which internal runner queue held the requests. If four or more are rejected, the run is compatible with global bound but not proof; if request arrivals skewed, mark INCONCLUSIVE. Check source and independent negative tests before making any deployment decision.

**No production guarantees:** Synthetic public CPU only; no tenant safety, memory pressure, DLE/cost authorization, bounded queue fairness, or sovereign HIL. A bespoke gateway or admission layer is NOT automatically justified by this observation; route changes require fail-closed scope+deadline evidence and comparisons to existing components. State remains DRAFT, no private GHA spend.
