# R12 — Existing reverse-proxy global admission primitive: nginx `limit_conn`

Owner [Model Spelunker #316](https://github.com/SemperSupra/model-spelunker/issues/316), source negative [PR #350](https://github.com/SemperSupra/model-spelunker/pull/350), dependent on existing streaming client #332. **Objective is reuse versus bespoke**, not shipping a new proxy.

R10 public CPU verified that with **hot loaded** Ollama 0.34.1 `OLLAMA_NUM_PARALLEL=1`, `OLLAMA_MAX_QUEUE=1`, six simultaneous direct clients all completed HTTP200; source branch in `getRunner` bypasses the bounded pending-runner queue. R12 uses the **same pinned Ollama and public Qwen3:1.7b instance and same six-client code** but sends the second treatment through an isolated on-runner **nginx** reverse proxy configured with `limit_conn_zone $binary_remote_addr` and `limit_conn ... 2`, status 503. The proxy listens only on loopback. No private network, tenant identity or credentials.

Experiment: first direct hot Ollama (RED), then proxy (BLUE), one model, one physical public CPU runner. All six requests are submitted before first completion; compare HTTP200 accepted and HTTP503/429 rejected, not content. Six synthetic prompts only. Reuse original `hot_queue_probe.py` and pinned model SHA; independent reducer `compare.py` checks both artifact shapes and their comparability. Record exact nginx installed package version and config SHA256 in evidence; the package is **not build-reproducibly pinned** in this first feasibility study, so security promotion requires later pin/attestation.

The admitted condition is narrow: at most two globally active/pending HTTP requests *from the same loopback client IP* pass the nginx layer in this one six-request cohort. `limit_conn` is based on source address; it is NOT a trustworthy identity/tenant/authorization boundary and cannot be blindly reused in proxy-chained deployments. It also does not prove fairness, deadlines, real-time preemption, multiple worker pods, or persistent job correctness. Different request arrival order and backend state may alter timing; this is admission-status qualification, not latency optimization.

Expected RED/BLUE: direct more than 2 HTTP200, proxy at most2 200 and at least4 HTTP503/429, with start spread <500ms and all submissions before earliest completion. Outcomes including regression or UNKNOWN are preserved; no production deployment or private GHA spend. This is candidate-screening evidence supporting later externally governed admission in gateway/IaC, not permission for bespoke scheduler or sovereign host changes.
