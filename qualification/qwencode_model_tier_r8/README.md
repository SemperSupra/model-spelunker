# R8 independent real Qwen CLI × 4B-Instruct local CPU task qualification

Authority: [#246](https://github.com/SemperSupra/model-spelunker/issues/246), [batch #224](https://github.com/SemperSupra/model-spelunker/issues/224), model qualification [#206](https://github.com/SemperSupra/model-spelunker/issues/206). This draft is stacked on [R7 source-pinned lean native test PR #245](https://github.com/SemperSupra/model-spelunker/pull/245); all new files are in this unique subtree and a scoped public CI workflow, with no modifications to the parent or private repository.

**Why:** the exact actual Qwen Code v0.28.3 + pinned Ollama/Qwen3:1.7b task failed repeatedly under large default and small overridden system prompts. The second R7 native run [44880291421](https://github.com/SemperSupra/model-spelunker/actions/runs/44880291421) confirmed `QWEN_SYSTEM_MD` worked (~1,361 system chars), disabled both `tool_search` and `tool_call`, and reduced complete request to ~12,369 bytes, but still returned no tool call/hidden fixture; `task_stop` remained a non-exempt advertised tool. The weaker model is **not accepted for this agent/task** even though it can produce direct model `read_file` tool selections in small synthetic test calls.

This R8 rep qualifies a distinct open-weight local model class, `qwen3:4b-instruct` (Qwen3-4B-Instruct-2507 Q4_K_M, approximately 2.5GB), inside one **disposable standard free-tier Ubuntu-24.04 GitHub Actions runner**. This is an *actual* Ollama model download and native Qwen Code standalone executable test, not an API mock. Verify exact Ollama 0.34.1 archive SHA256 and observed model manifest digest prefix `0edcdef34593` against a public listing; a mismatched tag refuses to run. After download, the local CPU model receives an unknown randomized `fixture.txt`, small source-backed `QWEN_SYSTEM_MD`, only direct `read_file` plus exempt `task_stop`, `tools.toolSearch.enabled=false`, default approval, bounded 4 tool calls and 280s wall budget. The bounded independent oracle requires an *actual native Qwen read_file tool delta*, exact final hidden file value, CLI exit success, observed prompt under 14KB/5,000 system chars and expected tool schema names. No user data, passwords or private URLs are sent to the model.

Two independent public GHA jobs run in parallel: the real model/CLI execution and fast source/negative security tests. The slow job has an 18-minute total cap including download and exits with error on model task failure, with redacted receipt and proxy metadata retained even when failed. No raw model output, prompt, hidden nonce or API credentials in CI artifacts. Source acceptance is not inference acceptance.

**Not qualified by this rep:** a real Windows Hyper-V guest or physical Windows host; BigMac/TrueNAS/GPU, actual provider/MCP memory projection, multi-agent teams, production YOLO or public cloud/private data sharing. The private host and credential effects remain behind [IaC #601](https://github.com/mark-e-deyoung/infrastructure-as-code-private/issues/601) / [Agent Dispatch #748](https://github.com/SemperSupra/agent-dispatch-private/issues/748) signed admission. No persistent installations or private GitHub Actions minutes, no auto-merge. A negative result must stay a negative task-model-runtime receipt.

The digest prefix is validated at run time; no claim of independent full-manifest signature verification is made. Later immutable acceptance should pin the complete manifest digest observed in the successful venue, not rely solely on this exploratory prefix.
