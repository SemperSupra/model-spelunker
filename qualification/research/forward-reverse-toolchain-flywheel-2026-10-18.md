## Ghidra's FLIRT-like machinery: source-grounded findings

**FID is Ghidra's closest native FLIRT analogue**, with source at [FidService.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/FunctionID/src/main/java/ghidra/feature/fid/service/FidService.java), [fid.xml](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/FunctionID/src/main/doc/fid.xml), and [Ghidra DevGuide](https://github.com/NationalSecurityAgency/ghidra/blob/master/DevGuide.md). It fingerprints labeled source/reference library functions, includes processor-specific matching, and can leverage parent-child relationships and compiler/library metadata. It creates writable `.fidb` and distributed read-only `.fidbf` databases. Hashes tolerate some relocation, not arbitrary optimization/source transformations. It is **not** native IDA `.sig` FLIRT-format compatibility. A reference library should retain real function names and sufficient bodies for ingest; avoid short/common collision-prone functions and leaking training names into the blind target.
- [BSim](https://github.com/NationalSecurityAgency/ghidra/blob/master/GhidraDocs/GhidraClass/BSim/README.md) is complementary, based on decompiler/data-flow signatures with tolerance for some different compilers/architectures/nearby source variants. Use local **H2** (no PostgreSQL/Elasticsearch/server) for a small source-known corpus; [H2 creation](https://github.com/NationalSecurityAgency/ghidra/blob/master/GhidraDocs/GhidraClass/BSim/BSimTutorial_Creating_Database_From_GUI.md), [headless bsim CLI](https://github.com/NationalSecurityAgency/ghidra/blob/master/GhidraDocs/GhidraClass/BSim/BSimTutorial_BSim_Command_Line.md). Compare similarity **and confidence**, not just maximum match score; BSim identifies candidates, not proof of source identity.
- **Avoid prematurely adopting third-party FID generators**: [threatrack/ghidra-fid-generator](https://github.com/threatrack/ghidra-fid-generator) is an instructive source-available automated ingestion precedent but describes historical Ghidra 9-era/CentOS 7 assumptions. Review exact current Ghidra API and use built-in FID/BSim first.
- Both have source available for inspection and controlled instrumentation. Do not distribute vendor library signatures without license and corpus-publication review. Hashes/fingerprints can leak proprietary function identity even if code is not uploaded.

## Minimal falsifiable FID-vs-BSim qualification

**Objective:** measure incremental correct known-library identification without leaking library names into the target's actor-facing view or overfitting tiny toy functions.

1. **Generate** a small synthetic public-safe library with a few nontrivial functions, real names/debug symbols and independently callable behavior vectors; at least two versions including a decoy/collision family. Build a static library `.a` and related **linked/stripped** ELF with identical source/library identity and frozen compiler/flags. The three-helper dispatcher in PR #184 is a starting control, not sufficient by itself to establish signature robustness.
2. **Fingerprint** original named reference objects with built-in Ghidra FID (`.fidb`), ingest source-known Ghidra project to **H2 BSim**. Keep labels and reference source in the evaluator workcell.
3. **Query** strictly blind stripped targets at same compile settings, changed optimization (`-O0/-O1/-O2`), changed linker/relocation and changed compiler where available, then later ARM64 COFF/Mach-O only after separately qualified loaders.
4. **Control** matched tasks: baseline function names/call graph; +FID; +BSim; +both. Every baseline treatment gets identical real target, Ghidra version, time and oracle; confidence below threshold or ambiguity must return UNKNOWN instead of naming a false library.
5. **Independent oracle** verifies precision, recall/coverage, false attribution, per-function known source identity, matching candidate rank, flags/ISA robustness and time/storage/cost. Include unrelated/mutated lookalike code and absent-library negative controls.
6. **Feed back** only independently confirmed library signatures and measured false-positive exclusions into the versioned FID/BSim reference corpus. Never automatically name unverified private functions, train on the evaluator mapping, or put proprietary signatures in public GHA.

**Venue:** existing free public standard GHA Ubuntu, using PR #184's already checksum-verified Ghidra 12.1.4 script only for a bounded explicitly admitted rep; do not re-enable the 570-MB download in routine CI. Small BSim H2 file avoids a server/cluster. Independent verifier remains outside any AI actor workcell. **No actor/model semantic recovery improvement or FID/BSim real test has yet been executed.**

## Candidate data contract, not a new platform

`producer/source_digest + compiler/linker/runtime commits and flags + ABI/ISA + build config (Kconfig/DTS/lockfile) + object/lib/binary digests + debug/IR/map references + known labeled functions + reverse tool and evidence digests + independent semantic oracle + acceptance state`.

Everything links by immutable digests. Store only bounded/public-safe input for free-cloud tests; keep sensitive build maps, symbols, proprietary libraries, target signatures and evaluator-only oracles on admitted private/sovereign planes. Model Spelunker qualifies configured actors; Agent Dispatch selects the eligible native/container/VM/GHA/Sovereign workcell. A confirmed independent match adds to the reference corpus; a failed match adds a negative-control fixture. This is the flywheel, not an extra plugin manager.
